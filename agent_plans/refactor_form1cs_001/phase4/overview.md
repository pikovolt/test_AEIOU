# Phase 4 Overview

## 全体目的
`Form1.cs` の入力責務分離を仕上げ、以下を達成する。

- 入力解釈と実行責務を分離し、保守時の影響範囲を限定する
- 移動/範囲選択の処理をコマンド層へ段階移管する
- VirtualMode 前提の回帰安全性を維持したまま、入力系の変更容易性を高める

## Phase4 スコープ
- 対象:
  - `KeyDown` 経路のコマンドディスパッチ整備
  - 移動/範囲選択処理のコマンド化
  - 数字/空セルなど値入力処理の責務明確化
- 非対象:
  - 大規模設計刷新（アプリ全体再設計）
  - 既存機能仕様の追加・変更
  - 性能KPI（P95）をGateとする最適化作業
  - `phase2/`, `phase3/` 履歴資産の再実装・再評価

## 実行順（依存）
1. **P4-001**: Phase3 SSOT整合（起点）
2. **P4-002**: 入力コマンド面の定義固定（P4-001依存）
3. **P4-003**: KeyCommandDispatcher導入（P4-002依存）
4. **P4-004**: MoveSelectionCommand導入（P4-003依存）
5. **P4-005**: 値入力コマンド分離（P4-004依存）
6. **P4-006**: 修飾キー判定の単一路線化（P4-005依存）
7. **P4-007**: 行削除（`Shift+Delete`）遅延の性能改善（P4-006依存）

## 依存ルール
- 1タスク = 1PR
- 1タスクの変更ファイル数は 3〜5 を上限とする
- 各タスクは主要Gateを1つだけ持つ
- 回帰確認は `checklists/smoke_phase4.md` に統一する
