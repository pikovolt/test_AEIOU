# P4-007: Shift+Delete の通知・再計算・再描画集約

## ステータス
- Done（2026-10-03）

## 対象範囲
- `ExecuteWriteGroup` の書き込みを `GridViewManager` のネスト可能なバッチ更新で囲んだ。
- バッチ中の `CellValueChanged` は列ごとの最終変更へ集約し、終了時に変更列だけ通知する。
- VirtualMode のセル単位 `InvalidateCell` はバッチ中に抑止し、既存呼び出し元の `Invalidate` 1回に集約する。
- Undo / Redo も同じバッチ経路で通知・セル再描画を集約する。

## Gate確認
- 既定設定（4列 × 1800行）で先頭1行を削除する構造上、変更セル数は7200件となる。
- 従来は最大7200回の列再計算（約1296万セル参照）と7200回の `InvalidateCell` が発生した。
- 変更後は4回の列再計算（7200セル参照）となり、セル単位の `InvalidateCell` は0回、呼び出し元の全体 `Invalidate` は1回となる。

## 計測記録
- 条件: 4列 × 1800行、各列を変更セル数と同じ1800回再計算する従来経路と、各列1回だけ再計算する集約経路を Python 3 の同一プロセスで比較した。
- 1回平均: 従来相当 370.204 ms / 集約後相当 0.236 ms。
- 10回平均: 従来相当 367.921 ms / 集約後相当 0.200 ms。
- この値は通知集約による計算量差を確認するアルゴリズム計測であり、WinForms の描画時間を含む実機GUI計測ではない。

## 回帰確認
- `git diff --check` で差分の形式エラーがないことを確認した。
- 静的検査で、`ExecuteWriteGroup` と Undo / Redo の全経路が `try/finally` でバッチを必ず終了することを確認した。
- 実行環境に .NET Framework 3.5 / MSBuild とGUIがないため、`Shift+Delete`、`BackSpace`、`Delete`、Undo / Redo の実機操作確認は未実施。
