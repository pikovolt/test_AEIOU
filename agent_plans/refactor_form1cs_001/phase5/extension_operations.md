# Phase 5 外部自動処理 — 配置・障害復旧手順

この文書は、信頼済みの外部自動処理 DLL を AEIOU に配置する利用者と、障害を切り分ける運用担当者向けの手順である。拡張 API の設計上の正本は [`extension_contract.md`](extension_contract.md)、動作確認の正本は [`checklists/smoke_phase5.md`](checklists/smoke_phase5.md) とする。

## 1. 運用上の前提

- 外部 DLL はサンドボックス化されず、AEIOU と同じ OS 権限で動く。出所と内容を確認できる DLL だけを配置する。
- 対象は本体と同じ .NET Framework 3.5、同じプラットフォームでビルドする。
- 探索場所は `AEIOU.exe` と同じディレクトリにある `Extensions` **直下**だけである。サブディレクトリは探索しない。
- 探索と登録は起動時に1回だけ行う。追加、更新、除去の前に AEIOU を終了し、変更後に再起動する。
- `AEIOU.Automation.Abstractions.dll` は本体横のものを共有する。拡張側のコピーを `Extensions` に配置しない。

## 2. 標準配置と確認

1. 編集中のシートを保存し、AEIOU を終了する。
2. 本体ディレクトリをバックアップする。
3. 本体と同じ構成でビルドされた拡張 DLL を `Extensions` 直下へコピーする。
4. AEIOU を起動し、右クリックメニューの **拡張自動処理** に期待する表示名が1件だけ出ることを確認する。
5. 破棄できるテストシートの小さい選択範囲で実行し、結果、Undo 1回、Redo 1回を確認する。
6. `automation-extensions.log` に新しいエラーがないことを確認してから実データで使用する。

ランダム整数サンプルの具体的なビルド、配置、実行、除去方法は [`AEIOU.Automation.Sample.Random/README.md`](../../../AEIOU/AEIOU.Automation.Sample.Random/README.md) を参照する。

## 3. ログと障害情報

読み込み時の診断は本体ディレクトリの `automation-extensions.log` に追記される。ログには日時、DLL パス、識別できた場合の command ID、例外または拒否理由が記録される。正常ロードだけの記録やセル内容は記録されないため、メニュー表示とテスト実行も併用する。

障害報告では次を控える。

- AEIOU と拡張 DLL の版、ビルド構成、OS
- 配置した DLL のファイル名一覧
- 発生日時、操作、選択範囲、入力パラメーター（機密のセル値は除く）
- `automation-extensions.log` の該当日時の行
- 拡張を除去した状態で再現するか

## 4. 共通の安全な切り戻し

拡張が原因と思われる場合は次の順に復旧する。

1. AEIOU を終了する。終了できない場合は、保存済みであることを確認してからプロセスを終了する。
2. `Extensions` を `Extensions.disabled` など本体が探索しない名前へ変更する。名前変更できない場合は、中の DLL をすべて別ディレクトリへ移動する。
3. AEIOU を再起動する。**拡張自動処理** が消え、四則演算、反転、置換、繰り返し、連番の組み込み処理が利用できることを確認する。
4. 必要なら退避した DLL を1件ずつ戻し、毎回再起動して原因 DLL を特定する。

拡張の失敗はロードまたは1実行単位で隔離されるが、DLL は信頼済みコードとして本体権限で動く。異常を確認したまま利用を継続しない。

## 5. 症状別の復旧

### 拡張を全除去したい

共通切り戻しを実施する。`Extensions` が存在しない、または空でも起動できる。拡張 DLL の読み込み結果は起動中には変わらないため、除去後は必ず再起動する。

### 契約バージョン不一致

ログの対象 DLL と契約バージョン拒否を確認し、その DLL を退避する。本体に同梱された `AEIOU.Automation.Abstractions.dll` を残し、その本体版向けに拡張を再ビルドする。古い本体 DLL や契約 DLLだけを上書きして組み合わせない。

### command ID が重複する

先に登録されたコマンドは維持され、後から見つかった外部コマンドは拒否される。ログで同じ ID の DLL を特定して両方退避し、提供者に一意で永続的な小文字 ASCII ID への変更を依頼する。組み込み ID と同じ外部コマンドは使用しない。

### DLL の依存ファイルが不足する

ログの `FileNotFoundException`、`FileLoadException`、`ReflectionTypeLoadException` 等と対象パスを確認する。拡張提供者が指定した .NET 3.5 対応の依存 DLL を本体と衝突しないことを確認して配置するか、対象拡張を退避する。無関係な DLL を推測で本体ディレクトリへ追加しない。

### constructor または読み込み時に例外になる

該当型は登録されず、他のコマンドの探索は続行される。対象 DLL を退避し、公開された引数なし constructor が環境依存処理や例外を発生させない版を提供者から入手する。

### 実行時に例外または不正結果になる

エラー通知後、対象範囲が部分更新されていないことを確認する。不正な座標、重複セル、null、変更件数超過、シート世代不一致は host が全件拒否する。シートを保存せず対象 DLL を退避し、再起動後に組み込み処理が動くことを確認する。実行例外は現状ロード診断ログには追記されないため、表示されたエラーと再現入力を障害報告へ記録する。

## 6. リリース前チェック

リリース担当者は Windows のクリーンな展開先で次を実施する。

1. `Release|x86` をリビルドし、Automation tests が全件成功する。
2. 拡張なしで起動し、組み込み6経路と Undo/Redo、STS、AE 連携、基本キー操作を確認する。
3. サンプル DLL を配置し、検出、実行、Undo/Redoを確認する。
4. 依存不足、constructor 例外、契約不一致、重複 ID の検証 DLL を同居させ、正常サンプルと組み込み機能が継続することを確認する。
5. サンプルを除去して再起動し、登録が消えて組み込み機能が維持されることを確認する。
6. 実施結果、環境、未実施項目を `p5_007_completion.md` に記録し、smoke checklist は実際に確認した項目だけを完了にする。
