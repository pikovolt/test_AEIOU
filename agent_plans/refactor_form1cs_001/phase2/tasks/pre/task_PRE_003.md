### ログ確認の共通手順（全チェックID共通）

ログ確認を伴う判定では、最低限次を統一して記録する。

- **対象ログファイル/出力先**: アプリケーションログ（ファイルパス）、標準出力、デバッグコンソール等の確認対象を明記する。
- **観測時間範囲**: テスト操作開始〜終了の時刻を範囲で記録する（例: `10:14:03〜10:16:40`）。
- **失敗判定キーワード**: `Exception` / `Error` / `Fatal` / `Unhandled` を基本とし、必要に応じて機能固有キーワードを追加する。

MUST項目（VM-PRE-01〜06）の `PASS` は、目視（または操作）結果と上記ログ確認が両方成立した場合のみ許可する。

### `N/A` 例外運用（MUST/SHOULD共通）

`N/A` を認めるのは、次のいずれかに該当し、かつ確認証跡を残せる場合のみとする。

1. **該当画面自体が未提供**: 対象UIがビルド/配布物に存在せず、手順上確認不能。
2. **機能フラグで完全無効化**: 環境設定・Feature Flagで対象機能が強制OFFされ、操作導線が存在しない。
3. **権限/契約プラン制約で非表示**: 権限設定やライセンス条件により対象機能へ到達不能。

`N/A` 記録時は、チェック結果記録テンプレートの「観測ログ」に以下を必須記載する。

- 適用条件（上記1〜3のどれか）
- 非適用理由（対象機能名、確認不能の根拠）
- 検証環境（画面ID、設定値、Feature Flag名、権限ロール等）
- 承認者（役割・氏名）
- 承認日時
- 関連証跡（設定ファイル、スクリーンショット、ログパス）

## IMPL着手可否判定
- MUST（VM-PRE-01〜06）は **全件 `PASS`** を原則とし、1件でも `FAIL` があれば着手不可。
- MUST（VM-PRE-01〜06）の `PASS` 条件は **目視/操作結果が期待どおり** かつ **ログ証跡（`logSource` / `logTimeRange` / `query/keyword` / `evidencePath`）が記録済み** の両立とする。
- MUST（VM-PRE-01〜06）の `N/A` 件数は **0件必須** とする。
- MUSTで `N/A` をどうしても使う場合は「`N/A` 例外運用（MUST/SHOULD共通）」および「MUSTで `N/A` を例外許容するための追加承認条件」の条件充足が必須。条件不足の `N/A` は `FAIL` と同等に扱う。
- SHOULD（VM-PRE-07〜12）は `PASS` を推奨し、`FAIL` は既知課題として持ち越し可（要チケット化）。
- SHOULDの `N/A` も例外運用の記録要件を適用し、記録不足時は未判定（持ち越し不可）とする。
- `N/A` を付与した項目は、適用条件・承認者・証跡リンクに加え、MUSTの場合はN/A理由と代替証跡IDを `task_VM2_001.md` 引き継ぎ情報に必ず転記する。

### 集計ルール（MUST/SHOULD）

- MUST集計:
  - 分母: VM-PRE-01〜06 の6件固定（`N/A` は原則禁止）。
  - 分子: `PASS` 件数。
  - 着手条件: 分母=分子 かつ MUSTの `N/A` 件数=0。
- SHOULD集計:
  - 分母: VM-PRE-07〜12 から、承認済み `N/A` を除いた件数。
  - 分子: `PASS` 件数。
  - 着手可否への直接ブロックはしないが、`FAIL`/未判定は全件をチケット化し、`task_VM2_001.md` に引き継ぐ。

## VM-PRE-07〜10 の代替観点（前提機能が非搭載の場合）
前提機能（ソート/フィルタ/列順変更）が非搭載で VM-PRE-07〜10 を `N/A` とする場合、代替として次を実施し、観測ログへ記録する。

> 代替観点の実施は、`N/A` 承認の補強証跡であり、承認記録（適用条件・承認者）そのものの代替にはならない。

- **スクロール境界**: 末尾行/末尾列、先頭復帰を反復し、表示欠落や例外がないことを再確認する（VM-PRE-03補強）。
- **編集確定再描画**: 連続編集（複数セル）後の確定/フォーカス移動で表示値と内部値が一致することを確認する（VM-PRE-04補強）。
- **選択追従**: 連続選択・キーボード移動で関連UI追従と遅延有無を確認する（VM-PRE-08深掘り）。
- **例外ログ**: 上記操作中の例外ログ有無を明示し、例外発生時は再現手順を併記する。

## MUST項目FAIL時の切り分け手順
MUST項目（VM-PRE-01〜06）がFAILの場合、以下の順序で切り分ける。

1. **イベント配線確認**: `CellValueNeeded` / `CellValuePushed` / `SelectionChanged` などの購読漏れ・重複登録・解除漏れを確認する。
2. **境界条件確認**: 0件、1件、末尾行/末尾列、最大件数近傍で同事象が再現するかを確認する。
3. **再描画/無効化確認**: `Invalidate` / `Refresh` / レイアウト更新有無と、処理中の一時無効化（再入防止）が適切かを確認する。
