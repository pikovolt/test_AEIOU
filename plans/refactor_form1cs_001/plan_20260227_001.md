## 目的

`Form1.cs` の責務分離を段階的に進め、最終的に VirtualMode 対応と入力応答性（P95 25ms 以内）を達成する。

## スコープ

- 対象: `AEIOU/WindowsFormsApplication1/Form1.cs`
- 関連: `GridViewManager.cs`, `GridViewOperation.cs`, `TimingCell.cs`, `Settings.cs` ほか
- 非対象: UIデザイン大幅変更、機能仕様の追加

## 実行ステップ

- [x] 1. 現状把握
  - [x] `Form1.cs` 内の責務を「入力」「描画」「モデル更新」「UI制御」に分類
  - [x] 既存イベント（`KeyDown`, `CellPainting`, `CellValueNeeded` 等）の依存関係を一覧化

- [ ] 2. A. 先行分離（安全に小さく切れる単位）
  - [x] A-1: `GridSelectionService` 相当を導入し、`Rect` 計算と `CurrentCell/Selected` 更新を委譲
  - [x] A-2: `GridScrollService` 相当を導入し、`scrolling*` 系を集約
  - [x] A-3: `GridCellStyleResolver` の素地を追加し、`CellPainting` の条件判定だけ先に移設
  - [ ] A-4: `Form1.cs` の選択更新ロジック（`setSelectRect` 系）の委譲範囲を段階拡張
  - [ ] A-5: `CellPainting` の `TimingCell` フラグ更新と実描画分離（resolver/renderer 分割）

- [ ] 3. モデル分離（Phase 1）
  - [ ] `TimingSheetModel` の責務・最小APIを確定
  - [ ] 直接的な `dataGridView` の値参照箇所をモデル経由に切替

- [ ] 4. VirtualMode 導入（Phase 2）
  - [ ] `VirtualMode = true` 切替
  - [ ] `CellValueNeeded` / `CellValuePushed` 実装
  - [ ] 行列同期の基点をモデルに統一

- [ ] 5. 描画分離（Phase 3）
  - [ ] `GridCellStyleResolver` の責務境界を固定
  - [ ] `GridCellRenderer` に `CellPainting` ロジックを移管

- [ ] 6. 入力分離（Phase 4）
  - [ ] `GridInputController` を導入
  - [ ] `KeyDown` の分岐をコマンド化
  - [ ] 選択制御を `SelectionController` に移管

- [ ] 7. 性能検証（Phase 5）
  - [ ] 4シナリオの P95/P99 測定
  - [ ] P95 > 25ms の場合はホットパスを特定して改善

## 完了条件（抜粋）

- [ ] `Form1` がイベント中継中心になっている
- [ ] 描画・入力・データ更新が各コンポーネントに分離されている
- [ ] 主要操作の回帰がない（手動スモークテスト）
- [ ] 入力→表示反映が P95 25ms 以内
