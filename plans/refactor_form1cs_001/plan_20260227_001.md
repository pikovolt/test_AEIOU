## 目的

`Form1.cs` の責務分離を段階的に進め、最終的に VirtualMode 対応と入力応答性（P95 25ms 以内）を達成する。

## スコープ

- 対象: `AEIOU/WindowsFormsApplication1/Form1.cs`
- 関連: `GridViewManager.cs`, `GridViewOperation.cs`, `TimingCell.cs`, `Settings.cs` ほか
- 非対象: UIデザイン大幅変更、機能仕様の追加

## 実行ステップ

- [x] 1. 現状把握
  - [x] `Form1.cs` 内の責務を「入力」「描画」「モデル更新」「UI制御」に分類
  - [x] 既存イベント（`KeyDown`, `CellPainting`, `CellValueNeeded` 等）の依存関係を一覧化

- [x] 2. A. 先行分離（安全に小さく切れる単位）
  - [x] A-1: `GridSelectionService` 相当を導入し、`Rect` 計算と `CurrentCell/Selected` 更新を委譲
  - [x] A-2: `GridScrollService` 相当を導入し、`scrolling*` 系を集約
  - [x] A-3: `GridCellStyleResolver` の素地を追加し、`CellPainting` の条件判定だけ先に移設
  - [x] A-4: `Form1.cs` の選択更新ロジック（`setSelectRect` 系）の委譲範囲を段階拡張
  - [x] A-5: `CellPainting` の `TimingCell` フラグ更新と実描画分離（resolver/renderer 分割）

- [ ] 3. モデル分離（Phase 1）
  - [ ] `TimingSheetModel` の責務・最小APIを確定
  - [ ] 直接的な `dataGridView` の値参照箇所をモデル経由に切替

### 3. モデル分離（Phase 1）実装計画（詳細化）

#### 3-1. 対象範囲の固定（先にやること）

- [ ] `Form1.cs` 内の「セル値読取/書込」直参照を、以下 3 区分で棚卸して優先順位を付ける
  - [ ] A: 入力ホットパス（`KeyDown` 経由で頻度が高い更新）
  - [ ] B: 一括操作（行列シフト、連番、置換など）
  - [x] C: ファイルI/O（保存/読込）
- [x] Phase 1 では **A を必須、B は影響小から着手、C は API 接続のみ（内部実装は現状維持可）** とする

#### 3-2. `TimingSheetModel` 最小責務（Phase 1 契約）

- [ ] モデル責務を「セル値・列名・行列サイズの正規データ保持」に限定する
- [ ] 表示制御（色/選択/スクロール）と WinForms コントロール操作はモデル責務に入れない
- [x] 例外方針を統一する（範囲外アクセスは `Try*` 系で吸収、通常 `Get*` は呼び出し側前提を明示）

#### 3-3. `TimingSheetModel` 最小API（Phase 1 で実装する面）

- [ ] セル値 API
  - [ ] `string GetCell(int col, int row)`（`CellValueNeeded` 想定で O(1) 取得を前提）
  - [ ] `bool TryGetCell(int col, int row, out string value)`
  - [ ] `void SetCell(int col, int row, string value)`
- [ ] 行列サイズ API
  - [ ] `int ColumnCount { get; }`
  - [ ] `int RowCount { get; }`
- [ ] 列名 API
  - [ ] `string GetHeader(int col)`
  - [ ] `void SetHeader(int col, string header)`
- [ ] Undo/Redo 連携 API（既存操作互換のため Phase 1 で先行）
  - [ ] `string SetCellWithUndo(int col, int row, string newValue)`（戻り値は oldValue）
  - [ ] `void ApplyUndoCell(int col, int row, string oldValue)`
  - [ ] `void ApplyRedoCell(int col, int row, string newValue)`

> 注: Undo/Redo の操作単位は既存 `SetValueOperation` を維持しつつ、値の実更新先を `DataGridView` 直書きから `TimingSheetModel` へ寄せる。

#### 3-4. 置換順序（差分最小で進める）

- [x] Step 1: 参照アダプタ導入
  - [x] `Form1` から `TimingSheetModel` を参照可能にし、初期化時に現行グリッド内容を同期
- [ ] Step 2: 読取先行置換
  - [x] `checkCellValue`、連続入力判定、描画判定用の値参照を `GetCell/TryGetCell` に置換（入力ホットパスを先行適用）
- [ ] Step 3: 単一セル書込置換
  - [x] テンキー入力・BS/Del・KaraCell 入力など単一セル更新を `SetCell` 経由に置換（`SetValueOperation` 連携）
- [ ] Step 4: 一括操作の段階置換
  - [x] 連番作成・反転の空セル判定/読取を `TryGetCellValue` ベースへ置換
  - [ ] `copyToCell`、`deleteRect`、連番、置換、加減乗除、行列シフト等を高頻度順で `SetCell` に寄せる
- [ ] Step 5: ヘッダ更新置換
  - [x] 列名編集・列挿入削除後のヘッダ操作を `GetHeader/SetHeader` 経由へ統一

#### 3-5. 同期戦略（Phase 1）

- [x] VirtualMode OFF のまま、当面は「モデル正」を前提に `dataGridView` へ反映（反映は adapter 経由に限定）
- [ ] 反映は既存再描画トリガ（`InvalidateCell` 等）を維持し、挙動差分を最小化
- [ ] Phase 2 移行時に `CellValueNeeded/CellValuePushed` へ接続するため、値取得口を `TimingSheetModel` に一本化

#### 3-6. Phase 1 実装ガードレール

- [ ] モデル内部データ構造は O(1) 取得前提（例: `string[,]`）とし、`CellValueNeeded` のホットパスで線形探索を禁止
- [ ] Phase 1 では Model を「データ入れ物 + 行列管理 + Undo/Redo 連携」に限定し、業務ロジック（連番生成/置換条件判定など）は移管しない

#### 3-7. Phase 1 完了条件（明文化）

- [ ] `Form1.cs` 内の入力ホットパスで `dataGridView[col,row].Value` 直参照が残っていない
- [ ] 主要一括操作（連番/置換/四則演算/行列シフト）の少なくとも 50% がモデル API 経由
- [ ] 手動スモークで既存操作回帰なし（入力、移動、範囲選択、Undo/Redo、保存/読込）
- [ ] PRごとの検証証跡（実行コマンド / 実行不可理由 / 代替確認）を記録し、評価根拠を明示する
- [ ] Phase 2（VirtualMode）着手時に API 追加なしで `CellValueNeeded/CellValuePushed` 接続できる状態になっている

- [ ] 4. VirtualMode 導入（Phase 2）
  - [ ] `VirtualMode = true` 切替
  - [ ] `CellValueNeeded` / `CellValuePushed` 実装
  - [ ] 行列同期の基点をモデルに統一

- [ ] 5. 描画分離（Phase 3）
  - [ ] `GridCellStyleResolver` の責務境界を固定
  - [ ] `GridCellRenderer` に `CellPainting` ロジックを移管

- [ ] 6. 入力分離（Phase 4）
  - [ ] `GridInputController` を導入
  - [ ] `KeyDown` の分岐をコマンド化
  - [ ] 選択制御を `SelectionController` に移管

- [ ] 7. 性能検証（Phase 5）
  - [ ] 4シナリオの P95/P99 測定
  - [ ] P95 > 25ms の場合はホットパスを特定して改善
