## 4. VirtualMode 導入（Phase 2）

### 4.1 系統分解（Exit Gate 独立）

- [ ] **VM-WIRE**: `VirtualMode=true` と `CellValueNeeded/Pushed` の配線成立
  - Exit Gate:
    - [ ] `dataGridView1.VirtualMode = true` が既定経路で有効化される
    - [ ] `CellValueNeeded` が `TimingSheetModel` 参照のみで値供給できる
    - [ ] `CellValuePushed` がモデル書込経路（Undo/Redo方針含む）に接続される
    - [ ] 既存の非VirtualMode前提コードを経由せず、読書込の最小往復が成立する

- [ ] **VM-SYNC**: Row/Column/CurrentCell/Selection の整合成立
  - Exit Gate:
    - [ ] Row/Column Count の変更が `VirtualMode` 表示とモデル件数で不整合を起こさない
    - [ ] `CurrentCell` の移動結果がモデル座標と常に一致する
    - [ ] 範囲選択（Selection）更新時に表示状態とモデル解釈が乖離しない
    - [ ] スクロール/再描画/再バインド相当操作後も同期不変条件を維持する

- [ ] **VM-REG**: 主要操作の回帰成立（編集・移動・貼付・Undo/Redo）
  - Exit Gate:
    - [ ] 編集（単セル/複数セル）で値反映と再表示が従来期待どおりに完了する
    - [ ] キー/マウス移動後のフォーカスセル・選択範囲が従来挙動を維持する
    - [ ] 貼付（矩形/単一）で境界条件を含む既存仕様の回帰がない
    - [ ] Undo/Redo が `CellValuePushed` 経由後も履歴整合を維持する

### 4.2 相互依存（実施順序）

- [ ] **WIRE → SYNC → REG** の順でゲート判定を実施する
- [ ] VM-SYNC 着手条件: VM-WIRE Exit Gate 全項目が完了していること
- [ ] VM-REG 着手条件: VM-SYNC Exit Gate 全項目が完了していること
- [ ] 逆流禁止: 後続系統で基盤変更が必要になった場合は、依存元 Gate を再オープンして再判定する

> Phase 2 は 3系統の独立 Gate で進捗管理し、完了判定は VM-REG Gate クローズをもって成立とする。
