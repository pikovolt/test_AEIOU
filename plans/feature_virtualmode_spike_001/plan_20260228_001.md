# VirtualMode スパイク検証 実行計画

- ワークストリーム: `feature_virtualmode_spike_001`
- ベース設計（上位SSOT）: `/architecture.md`
- 作成日: 2026-02-28
- 更新日: 2026-02-28（plan-only main反映運用を追記）

## 目的
`DataGridView` の `VirtualMode = true` 移行に向けた最大の不確実性（接続性と性能）を、本流のロジックから切り離して検証する。
同時に、Phase 1で課題となった「性能KPI（P95 <= 25ms）の測定プロトコル」を先行して確立する。

## スコープ
- 対象: `Form1.cs` 内の `DataGridView` 初期化処理、および性能測定用の一時コード
- 非対象: 実モデル（`TimingSheetModel`）との結合、既存の Undo/Redo 操作の完全な互換性維持（本スパイクではダミーデータを用いるため）

## ブランチ運用方針（今回の前提）
- `main` に反映するのは `plans/` 配下のドキュメント変更のみ。
- スパイク実装（`AEIOU/...` のコード変更）は作業ブランチ内に閉じ、`main` へは取り込まない。
- そのため、コミットは次の2系統に分離して管理する。
  - **A系統（main反映対象）**: `plans/...` の更新コミット
  - **B系統（main非反映）**: 実装検証用コミット

## 実行ステップ（編集前提）

- [ ] **1. 変更の分離ルールを先に固定**
  - [ ] 作業開始前に「plan編集」と「実装検証」を同一コミットに混在させないと宣言する。
  - [ ] `git status` で差分を確認し、`plans/` 以外の変更がある場合はA/Bどちらに属するか都度仕分ける。

- [ ] **2. Plan更新（A系統）を先行実施**
  - [ ] 本ドキュメントのチェック項目を更新する。
  - [ ] 測定プロトコル・検証観点・完了条件を必要に応じて追記する。
  - [ ] A系統コミットを作成する（`plans/` のみをステージ）。

- [ ] **3. スパイク実装（B系統）を分離実施**
  - [ ] `dataGridView1.VirtualMode = true;` を設定。
  - [ ] `CellValueNeeded` / `CellValuePushed` を仮実装し、ダミーデータで疎通を確認する。
  - [ ] `Stopwatch` ベースの計測コードを追加し、取り外し容易な形にする。
  - [ ] B系統コミットを作成する（実装ファイルのみ）。

- [ ] **4. mainへはA系統のみ反映**
  - [ ] A系統コミットのみを `main` に取り込む（`cherry-pick` もしくは plan-only PR）。
  - [ ] B系統コミットは作業ブランチに残し、`main` へはマージしない。

- [ ] **5. 検証結果をドキュメント化**
  - [ ] 手動検証シナリオの結果（P95、再現手順、観測ログ）を `plans/` 配下の記録へ追記する。
  - [ ] main反映時に「実装未反映」である旨をPR本文に明記する。

## 完了条件 (Exit Gates)
- [ ] `main` に取り込まれるコミットが `plans/` 配下のみで構成されていること。
- [ ] スパイク実装は作業ブランチ上で再現可能だが、`main` には存在しないこと。
- [ ] P95 の測定結果（ms）と判断メモが `plans/` 配下に記録されていること。
