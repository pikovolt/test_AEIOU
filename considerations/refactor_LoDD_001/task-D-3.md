# task-D-3: タスク完了時の「5分チェック」の実現可能性

## ステータス
- **状態**: 完了
- **更新日**: 2026-03-07

## タスク概要
元文書・v1.1 ともに「AI生成コードの各関数の意図を1行で説明できるか確認」を5分以内としている。500行×十数モジュール規模で、1タスクあたりの変更範囲が3〜5ファイルの場合、5分は過小ではないか。特に理解負債の検知は読解を伴うため、見積もりの根拠が不明。

## 詳細分析

### 現状の問題
- **時間見積もりの根拠不明**: 元文書・v1.1 ともに「5分以内」と定めているが、その根拠（想定コード量、関数数、1関数あたりの確認時間など）が記載されていない
- **スケールとの乖離**: 想定する規模（500行×十数モジュール、1タスクで3〜5ファイル変更）において、各関数の意図を1行で説明しながら確認する作業が5分で完了するかが疑問
- **「理解負債の検知」の特性**: 読解を伴う作業であり、単純な検索・確認作業と異なる認知負荷がかかる。機械的な時間見積もりが困難
- **運用上のリスク**: 「5分」という制約が形骸化し、チェック自体がスキップされるか、あるいは「5分でできる範囲のみ確認する」という不完全な運用につながる可能性がある

### 影響範囲
- `LoDD_Reference_v1.1.md` のタスク完了時チェック（軽量返済）セクション
- 「5分チェック」の定義・スコープ・完了条件
- Retrospective の `iterations` との関連（チェックが不完全だと iterations の正確性も下がる）

## 対応方針

### 確認項目
1. 元文書「AI Debt and LoDD Schedule Design.md」における「5分チェック」の定義と根拠を確認
   - 想定コード量・関数数
   - 「各関数の意図を1行で説明できるか」の具体的な確認方法
   - 「5分」の根拠（あれば）
2. v1.1 での「5分チェック」の記述箇所と内容を確認
3. 現実的な見積もりを行い、以下の選択肢を検討：
   - 「5分」の数値を実態に合わせて修正（例: 変更ファイル数×N分）
   - チェックのスコープを限定（「変更した関数のみ」など）
   - 「5分」を目安として残し、スコープを明確化する注記を追加
   - Retrospective の記録（iterations）でカバーされると整理する

### 修正対象
- `LoDD_Reference_v1.1.md` の軽量返済（タスク完了時チェック）セクション

### 完了条件
- [x] 元文書の「5分チェック」の定義と根拠を確認した
- [x] 現実的な運用が可能な記述に修正された（または根拠付きで「5分」が妥当と確認された）
- [x] チェックのスコープ（何を確認するか）が明確になった

## 備考
「5分」という数値が象徴的な意味（「短時間で終わるよう設計する」という意図）で使われている場合は、その旨を注記として追加することで運用上の混乱を防げる。数値の修正よりもスコープの明確化が優先度として高い。

## 対応記録

### 元文書の「5分チェック」確認結果
元文書「AI Debt and LoDD Schedule Design.md」の該当箇所:
```
## タスク完了時チェック（5分以内）
- [ ] Retrospective の3値を記入した
- [ ] iterations/ に knowledge/ に転記すべき内容がないか確認した
- [ ] 自分がAI生成コードの各関数の意図を1行で説明できるか確認した
      → 説明できない関数があれば、返済スプリントの対象としてマークする
```

「5分」の根拠は元文書に明記されていない。想定スケール（500行×十数モジュール）に照らすと、コードベース全体の関数意図確認は5分では不可能。しかし元文書の文脈を読むと、「各タスク完了時」のチェックであり、タスクの Context Boundary で限定されたスコープ（3〜5ファイル、変更した関数のみ）が暗黙的に前提となっていた。

### 問題の本質
1. **スコープの暗黙性**: 「AI生成コードの各関数」が「コードベース全体」と読める記述になっている
2. **「5分以内」の厳密性**: 厳密な時間制限と捉えると形骸化する。設計意図は「軽量であるべき」ということ
3. **超過時の扱い**: チェックが5分を超えた場合のガイダンスがない

### 修正内容
`LoDD_Reference_v1.1.md` のタスク完了時の軽量返済セクションに以下を反映:
1. セクション見出しを「5分以内」→「5分目安」に変更
2. スコープを明示する注記を追加:
   - チェック対象は **当該タスクで変更・生成した関数のみ**（コードベース全体ではない）
   - 「5分」は軽量であるべきという設計意図を示す目安
   - 日常的に長時間化する場合はタスク粒度が粗すぎる兆候として Retrospective で記録
3. 関数意図確認の項目に「当該タスクで変更した関数のみ」を明記
4. タスク実行フロー図・サイクル全体図の「軽量返済（5分）」表記も「5分目安」に統一

### 判断
備考の想定どおり、数値修正よりもスコープ明確化を優先した。「5分以内」を「5分目安」に変更し、スコープを明示する注記を追加することで、運用上の混乱（形骸化・スキップ）を防止できる。
