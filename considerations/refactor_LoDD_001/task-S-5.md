# task-S-5: 「AI負債の可視化」フロー内の構成要素の関係整理

## ステータス
- **状態**: 未了
- **更新日**: 2026-03-07

## タスク概要
v1.1 の6番目防壁「AI負債の可視化」は、現状1つのエントリとして表現されているが、その実現手段は複数の概念・フェーズにまたがっている。これらを一括りにして扱う現行方針は維持しつつ、各構成要素の関係性を整理し、v1.1 の記述をより読みやすくすることを目的とする。

## 背景
- task-S-1 の方針決定により、「セマンティックドリフトの検知」はマクロ視点で「AI負債の可視化」と同概念として扱われ、1つの防壁に統合されている
- task-S-2 の分析で、防壁テーブルの実現手段欄に `（直列）/ （並列時）` という条件分岐が混在することの**可読性問題**が指摘された
- フローとして見ると、以下は概念的に別々のステップだが、現状は1エントリに集約されている：
  1. セマンティックドリフトの検知（並列時：Contract Test + Merge Gate）
  2. AI負債の可視化（Debt Markers による潜在的負債の顕在化）
  3. 負債のマーク（Debt Markers の記入）
  4. 返済スプリント（計画的な返済の実施）
- 「フローの詳細化は別で考える」方針に基づき、本タスクで詳細化の方向性を検討する

## 詳細分析

### 現状の問題
- **防壁テーブルの記述**: `Debt Markers + 返済スプリント（直列）/ Contract Test + Merge Gate（並列時）` という実現手段が、直列・並列の両モードを1セルに詰め込んでいる
- **可読性の低下**: 現行運用（直列）のユーザーにとって、`（並列時）` の手段は現時点で不要な情報であり、読者を混乱させる可能性がある
- **フローとテーブ���の乖離**: v1.1 の「AI負債管理」セクションにはフローの詳細が記述されているが、防壁テーブルとの対応関係が明示されていない

### 影響範囲
- `LoDD_Reference_v1.1.md` の防壁テーブル（6番目エントリの記述）
- `LoDD_Reference_v1.1.md` の「AI負債管理」セクション
- `LoDD_Reference_v1.1.md` の「エージェント並列化への拡張パス（参考）」セクション

## 対応方針

### 確認項目
1. v1.1 の「AI負債管理」セクションにおける各ステップの記述を確認し、防壁テーブルとの対応関係を整理する
2. 防壁テーブルの実現手段欄を、現行運用（直列）を主軸として読めるよう再表現できるか検討する
3. 並列時の拡張手段（Contract Test + Merge Gate）は、拡張パスセクションへの参照を防壁テーブルに追記する形で表現できるか検討する

### 修正対象（検討）
以下のいずれかの表現案を検討する：

**案A: 防壁テーブルの実現手段を直列主軸に整理し、並列時は注釈で参照**
```
Debt Markers + 返済スプリント ※並列時は「拡張パス」参照
```

**案B: 防壁テーブルは直列手段のみとし、並列手段は拡張パスセクションに一本化**
```
Debt Markers + 返済スプリント
```
（並列時の Contract Test + Merge Gate は「拡張パス」セクションにのみ記載）

**案C: 現状維持**
```
Debt Markers + 返済スプリント（直列）/ Contract Test + Merge Gate（並列時）
```
（一括りとして許容し、フロー詳細化は v1.2 以降に委ねる）
