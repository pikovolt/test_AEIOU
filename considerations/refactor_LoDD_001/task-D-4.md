## 詳細分析

### 現状の問題
- **図の粒度差**: 元文書の「サイクル全体像」図と v1.1 の「サイクル全体」図で、同じ概念が異なる粒度・位置で表現されている
- **`iterations/ → knowledge/ 転記の確認` の扱い**:
  - 元文書: サイクル全体像図において明示的なステップとして記載
  - v1.1: 実装フェーズのタスク完了時チェック内に記載（軽量返済の一部）
- **意味の同一性と表現の差異**: 概念的には同じ内容だが、サイクル図と個別チェック項目という異なる文脈に置かれているため、「どちらが正しいか」「どちらを見れば全体を理解できるか」が不明瞭

### 影響範囲
- `LoDD_Reference_v1.1.md` のサイクル全体図セクション
- タスク完了時チェック（軽量返済）の `iterations/ → knowledge/` 転記ステップ
- サイクル全体の理解のしやすさ

## 対応記録

### 差分分析

元文書のサイクル全体像図（実装フェーズ部分）:
```text
├─ 実装フェーズ（Day 2〜N-2）
│    各タスク完了時:
│    ├─ Retrospective（3値記録: 5分）
│    ├─ Debt Markers（負債の可視化: 5分）
│    └─ iterations/ → knowledge/ 転記の確認
```

v1.1 のサイクル全体図（修正前）:
```text
├─ 実装フェーズ（Day 2〜N-2）
│    各タスク完了時:
│    ├─ 軽量返済（5分）
│    ├─ Retrospective 記入
│    ├─ Debt Markers 記入
│    └─ iterations/ パージ + knowledge/ 転記検討
```

差分のポイント:
1. **`iterations/ パージ` と `knowledge/ 転記検討` の結合**: v1.1 では `+` で結合されているが、これらは概念的に異なる操作（パージ = 削除、転記検討 = 知識保存）。元文書では `iterations/ → knowledge/ 転記の確認` のみが明記され、パージは別の文脈で扱われている
2. **実行順序の暗黙性**: knowledge/ への転記を検討してからパージすべきだが、`+` で結合すると順序が不明瞭になる。v1.1 のワークフローセクション「iterations/ のパージ」（確認 → 転記 → 削除の順序）と整合させるには、分離して順序を明示すべき
3. **v1.1 のタスク実行フロー図**: 別の箇所（ワークフロー > タスク実行）では `iterations/ パージ` と `knowledge/ への転記を検討` が既に分離されている。サイクル全体図のみ結合されていた不整合がある

### 修正内容
`LoDD_Reference_v1.1.md` のサイクル全体図において:
- `iterations/ パージ + knowledge/ 転記検討` を2行に分離
- `iterations/ → knowledge/ 転記検討` を先に配置し、`iterations/ パージ` を後に配置（v1.1 のワークフロー「iterations/ のパージ」セクションの実行順序と整合）

修正後:
```text
├─ 実装フェーズ（Day 2〜N-2）
│    各タスク完了時:
│    ├─ 軽量返済（5分目安）
│    ├─ Retrospective 記入
│    ├─ Debt Markers 記入
│    ├─ iterations/ → knowledge/ 転記検討
│    └─ iterations/ パージ
```

### 判断
v1.1 内部で既に存在していた不整合（ワークフローセクションでは分離済み、サイクル全体図では結合）を解消した。意味の変更はなく、表記の統一のみ。元文書との表現差も解消された。
