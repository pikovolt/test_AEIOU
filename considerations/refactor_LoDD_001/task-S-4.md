# task-S-4: Contract Test の位置付けの曖昧さ

## ステータス
- **状態**: 完了
- **更新日**: 2026-03-07

## タスク概要
v1.1 の拡張パスでは `tests/contracts/` を新設するとあるが、元文書では Contract Test の詳細（テストコード例、配置構造、テスト種別テーブル）が記載されている。この詳細情報が v1.1 に圧縮された際に落ちている。拡張パスを実際に着手する際に元文書を参照しないと実装判断ができない。

## 詳細分析

### 現状の問題
- **情報の圧縮**: 元文書に記載されていた Contract Test の詳細情報（テストコード例、配置構造、テスト種別テーブル）が v1.1 への統合時に圧縮・脱落している
- **実装判断の依存**: 拡張パス（`tests/contracts/` 新設）を実際に着手する際、v1.1 単体では実装方法を判断できず、元文書の参照が必要になる
- **SSOT 原則への違反**: 元文書を参照しなければならない状況は、v1.1 を SSOT とする設計に反する

### 影響範囲
- `LoDD_Reference_v1.1.md` の拡張パスセクション（`tests/contracts/` 新設に関する記述）
- Contract Test の実装詳細（テストコード例・配置構造・テスト種別テーブル）
- task-S-3 の「元文書のアーカイブ化」判断に影響

## 対応方針

### 確認項目
1. 元文書「Semantic Drift Issues in Agent Parallelization.md」に記載されている Contract Test の詳細情報を確認
   - テストコード例の内容と種別 → **確認済み。元文書のみに存在する。**
   - `tests/contracts/` の配置構造 → **確認済み。元文書のみに存在する。**
   - テスト種別テーブルの内容 → **確認済み。元文書のみに存在する。**
2. v1.1 の拡張パスセクションに現状どの程度の情報が記載されているかを確認 → **「`tests/contracts/` を新設し統合前に検証する」という目的の記述のみ。実装詳細はない。**
3. 詳細情報を v1.1 の拡張パスセクションに追記する場合の記述量・位置を検討 → **追記しない方針に決定（v1.1 は変更ゼロ）。**
4. 詳細情報を `knowledge/` や別ドキュメントに切り出す案も検討 → **採用しない。元文書を補足資料として overview.md に明示する方針で対応。**
