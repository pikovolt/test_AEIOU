# task-D-1: 選択肢A/B/Cの議論経緯が v1.1 から脱落

## ステータス
- **状態**: 未了
- **更新日**: 2026-03-07

## タスク概要
元文書は3つの返済タイミング選択肢を比較評価し「Cの変形」を推奨している。v1.1 では結論（返済スプリントのサイクル組み込み）のみ記載。なぜこの方式を選んだかの根拠が v1.1 単体では追えない。

## 詳細分析

### 現状の問題
- **選択肢の比較評価の脱落**: 元文書で行われた選択肢A・B・C の比較評価（それぞれの利点・欠点・適用条件）が v1.1 に統合されていない
- **結論のみの記載**: v1.1 では「返済スプリントをサイクルに組み込む」という結論のみが記載されており、その根拠が追えない
- **意思決定の追跡不能**: なぜ選択肢A・B ではなく C の変形が採用されたかを v1.1 単体で理解できないため、将来的な見直しや変更の判断が困難になる

### 影響範囲
- `LoDD_Reference_v1.1.md` の返済スプリント・サイクル設計に関するセクション
- AI負債返済タイミングの設計根拠の記録
- 将来 v1.1 を改訂する際の意思決定の継続性

## 対応方針

### 確認項目
1. 元文書「AI Debt and LoDD Schedule Design.md」の選択肢A・B・Cの内容を確認
   - 各選択肢の返済タイミング・メカニズム
   - 各選択肢の評価（利点・欠点・適用条件）
   - 「Cの変形」を推奨した根拠
2. v1.1 の該当箇所に選択肢の比較評価を追記すべきか、`decision_log.md` に記録すべきかを判断
3. 詳細な比較評価を `knowledge/` に切り出す案も検討

### 修正対象
- `LoDD_Reference_v1.1.md` 該当セクション（根拠への参照または概要追記）
- または `plans/refactor_LoDD_001/<phase>/decision_log.md` への議論経緯の記録

### 完了条件
- [ ] 元文書の選択肢A・B・Cの比較評価内容を確認した
- [ ] 「Cの変形」が採用された根拠が v1.1 または decision_log.md から追跡できる状態になった
- [ ] 将来の改訂時に意思決定の根拠を参照できる体制が整った
- [ ] 修正内容が decision_log.md に記録された

結論の根拠を v1.1 本文に追記するか decision_log.md に記録するかは、記述量と v1.1 の読みやすさのバランスで判断する。LoDD の「SSOT を軽量に保つ」原則を踏まえると、詳細比較は decision_log.md への記録が適切な可能性が高い。
